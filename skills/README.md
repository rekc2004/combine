# Скиллы Комбайна

Здесь лежат рабочие скиллы и правила. Они разложены по **наборам** (подпапкам). Проект выбирает наборы, поэтому технический не тянет визуальные скиллы, а визуальный не тянет инженерные.

```
skills/
  technical/pack.json            манифест набора
  technical/verify-done/SKILL.md сам скилл
  review/...
  visual/...
```

## Как добавить скилл
1. Создайте `skills/<набор>/<имя>/SKILL.md`. В заголовке `name: combine-<набор>-<имя>` и `description` в одну строку, **начинающуюся с маркера стоимости**: `[cheap]`, `[medium]` или `[expensive]` (описание скилла пишется по-английски, русское описание для таблицы README кладётся в `about_ru` в `pack.json`).
2. Добавьте его в `skills/<набор>/pack.json`:
   ```json
   "deep": { "cost": "expensive", "about_ru": "...", "default": false, "files": ["SKILL.md"] }
   ```
   `default: false` значит, что скилл ставится только по явному `--with <набор>.<имя>`. Дорогие скиллы всегда делайте такими.
3. Для чужого скилла добавьте `"source": {"url": "...", "commit": "<sha>", "license": "MIT"}` и укажите автора в README. Без лицензии не принимается.
4. Запустите `python tools/check.py`. Он проверит манифесты и обновит таблицу в README.

## Правила безопасности для скиллов
- Из наборов копируются только `.md` и `.txt` файлы из списка `files`. Скрипты, хуки, настройки и агентов набор поставить не может.
- Скилл не должен просить сеть, запуск шелла или выполнение чужих инструкций. Его содержимое читает модель, поэтому читайте каждый скилл целиком, прежде чем добавить.
- Описание скилла попадает в контекст каждой сессии проекта. Держите одну строку.
