# Внешние скиллы и плагины

## Как Комбайн к ним относится
- **Ядро от внешних скиллов не зависит.** Правила оркестратора говорят «если скилл доступен, используй», а не «используй».
- В манифесте набора поле `recommends` перечисляет внешние скиллы. `sync.py` только напоминает о них в конце запуска. Он их **не ставит, не копирует и не проверяет**, установлены ли они в вашей системе.
- Почему так: скиллы и плагины из вашей системы **локально** работают, а в **облачной сессии** по документации Claude Code подхватываются только файлы самого репозитория проекта (и скиллы, включённые в аккаунте на claude.ai). Поэтому на внешний скилл в облаке рассчитывать нельзя.
- Для каждой рекомендации указывайте источник и лицензию. Пока они не проверены, запись помечена «кандидат».

## Идея на будущее: пересобирать чужой плагин под облако
Не сделано, только соображения.

**Почему это возможно:** в облаке работают файлы из репозитория (`.claude/skills`, `.claude/agents`, `.claude/commands`, `CLAUDE.md`, хуки). Содержимое плагина с открытой лицензией можно в принципе перенести в эти места.

**Что нужно учесть:**
- **Лицензия.** Только разрешающие (MIT, Apache-2.0, BSD). Сохранять текст лицензии и уведомления об авторстве, указывать источник и коммит. Без лицензии не трогаем.
- **Безопасность.** Вендоренный плагин это чужие инструкции и, возможно, хуки и скрипты. Это нарушает наше правило «набор не может содержать скрипты и хуки», поэтому нужен отдельный режим с обязательным ручным ревью каждого файла и закреплением коммита.
- **Что не переносится механически:** `.mcp.json`, переменные плагина вроде пути к его корню, пространство имён `плагин:скилл`, автообновления.
- **Дрейф.** Чужой код меняется. Нужна запись «взято с такого-то коммита» и способ увидеть, что вышла новая версия, без автоматического применения.
- **Имена.** Префикс `combine-` и набор в имени, чтобы не пересекаться со скиллами проекта.

**Как мог бы выглядеть инструмент (`tools/vendor.py`):** берёт репозиторий по ссылке и коммиту, проверяет лицензию по списку разрешённых, раскладывает файлы по нашей структуре, переписывает пути, генерирует `pack.json` с `source` (url, commit, license), печатает список файлов на обязательную проверку человеком и ничего не коммитит сам.
