# Диагностика: почему субагент не вызывает субагентов в облаке

Контекст: в облачной сессии (claude 2.1.295) субагент не нашёл инструмента Agent, хотя документация разрешает вложенность до трёх уровней, а локально вложенный вызов сработал (`docs/CONTROLS.md`, раздел про вложенность). Здесь диагностика, которая отделяет гипотезы: (а) переменная глубины в облачном окружении, (б) отличие облачной среды от документации.

Дёшево: простая сессия без этапов проекта, модель Haiku (или любая) для всей сессии, около нескольких центов [оценка, не измерено]. Запускать в **том же окружении Custom**, что и эксперимент, на репозитории с Комбайном (например `rekc2004/chervotochina`, ветка `main`; ветка выбрана до старта сессии).

## Промпт (вставить в новую облачную сессию)
```
Диагностика окружения. Ничего не меняй, файлов не создавай. Отвечай коротко и дословно, без интерпретаций.
1. Выполни в Bash и приведи вывод дословно: `claude --version`; `echo "REMOTE=$CLAUDE_CODE_REMOTE"`; `echo "DEPTH=$CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH"`; `echo "CONC=$CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS"`; `echo "FORK=$CLAUDE_CODE_FORK_SUBAGENT"`; и только ИМЕНА (без значений) переменных окружения, в названии которых есть CLAUDE или ANTHROPIC: `env | cut -d= -f1 | grep -i -E 'CLAUDE|ANTHROPIC'`.
2. Перечисли точные имена твоих собственных инструментов (основная сессия) и напиши, есть ли среди них Agent.
3. Вызови субагент типа general-purpose (параметр model: haiku) с заданием: «Перечисли точные имена всех инструментов, которые тебе доступны (включая отложенные), и напиши, есть ли среди них Agent. Если Agent есть, вызови через него любой субагент с поручением ответить словом ok и приведи результат дословно, включая текст ошибки. Если Agent нет, выполни поиск через ToolSearch по запросу «agent» и приведи, что нашёл.»
4. Если среди типов агентов есть combine-scout, вызови его с заданием: «Перечисли точные имена доступных тебе инструментов и напиши, есть ли среди них Agent. Ничего не вызывай.»
5. В конце таблица: тип агента | есть ли Agent в его инструментах | результат вложенного вызова | дословный текст ошибки (если была).
```

## Как читать результат
| Результат | Вывод |
|---|---|
| `DEPTH=1` (или малое число) | причина (а): задана переменная в облачном окружении; убрать её или поставить 3 |
| `DEPTH` пусто, у general-purpose нет Agent | причина (б): отличие облачной среды от документации; сообщить через `/feedback`; пока считать, что агентов вызывает только основная сессия |
| `DEPTH` пусто, у general-purpose Agent есть, вложенный вызов сработал | предыдущая неудача была в чём-то ином (например в самом задании или в типе агента, который вызывали); повторить Э-1 из `docs/EXPERIMENTS.md` |
| у `combine-scout` нет Agent | это ожидаемо: в его `tools` Agent не указан |

Результат (версия, значения переменных, таблица) внести в `docs/EXPERIMENTS.md`, Э-1.
