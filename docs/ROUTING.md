# Маршрутизация: почему роли, а не модели

До 0.3.0 комбайн распределял работу по моделям и effort (тогда `core/models.json`: scout на Haiku, builder на Sonnet, architect и security на Opus; теперь единый `core/agents.json`). В Kimi Code поля `model`/`effort` из agent-файлов игнорируются ([документация](https://www.kimi.com/code/docs/en/kimi-code-cli/customization/agents.html), Agent File Format). Без настроенного subagent model pool субагенты наследуют модель вызывающего; pool является необязательным host-контролем, а не основой Combine.

## Что вместо этого
Роль агента = набор инструментов + ограничения в теле + чёткое задание от оркестратора. Роли живут в `core/agents.json`, файлы для Kimi генерируются в `plugin/agents/combine-*.md` при сборке плагина.

| Агент | Инструменты | Класс работ |
|---|---|---|
| `combine-scout` | Read, Grep, Glob, Bash | поиск, чтение, сбор фактов, прогон проверочных команд; ничего не правит |
| `combine-skeleton` | Read, Grep, Glob, Edit, Write, Bash | каркас по утверждённому плану: структура, заглушки, конфиги, сборка |
| `combine-builder` | Read, Grep, Glob, Edit, Write, Bash | реализация поверх принятого скелета, тесты, багфиксы |
| `combine-architect` | Read, Grep, Glob, Write | архитектура, протоколы, модель угроз, декомпозиция; без запуска команд |
| `combine-security` | Read, Grep, Glob, Bash | ревью безопасности, только чтение и проверочные команды |

Все с `subagents: []` — один уровень делегирования, как в Claude-версии.

## Что пережило перенос из модельной логики
- **Поиск отдельно от проектирования.** Было «Haiku ищет, Opus проектирует» — стало «scout ищет, architect проектирует». Разделение труда сохранилось, мотивация та же: главный контекст не засоряется обходом репозитория.
- **Явные инструкции дешёвым исполнителям.** Наблюдение «слабая модель без явной инструкции не обратится за помощью» переносится на агентов целиком: в задании пишем, что проверить и как отчитаться (pipeline.md, CORE.md п.5–6).
- **Приёмка скелета главной сессией.** Агент может отчитаться без проверки — приёмку делает оркестратор фактическим запуском сборки и тестов.
- **Сначала рычаг задания, потом смена исполнителя.** Было «сначала effort, потом модель» — стало «сначала сузить задание и дать контекст, потом передать другому агенту».

## Необязательные host-контроли
- Kimi subagent model pool может задать отдельный alias для нового субагента; без pool используется наследование. Combine не требует этой настройки.
- «Effort как рычаг» не переносится механически: сначала размер задания, evidence и лимит отчёта. Модельные настройки проверяются отдельно на реальных задачах.
- Для независимых implementation missions Kimi Tower изолирует branch/worktree; обычный субагент изолирует только контекст.
