# Управление моделью и измерение расхода

Сведено по официальной документации Claude Code и Anthropic на 2026-10-09 (code.claude.com/docs, platform.claude.com/docs). Метки: **[П]** прочитано на странице, **[НП]** не найдено или страница прочитана не целиком, **[Н]** наблюдение в нашей работе (не документация). Версии Claude Code меняются быстро: проверяйте по ссылкам.

## 1. Как задать модель и effort

### Основная сессия (дирижёр)
| Что | Как | Метка |
|---|---|---|
| Модель | команда `/model`, флаг `--model`, переменная `ANTHROPIC_MODEL`, ключ `model` в settings.json (строка: алиас или полный id, например `claude-opus-5-5`). Приоритет сверху вниз: `/model`, `--model`, `ANTHROPIC_MODEL`, `model` в настройках; `ANTHROPIC_DEFAULT_MODEL` действует, только если ничего из перечисленного не задано | [П] code.claude.com/docs/en/model-config |
| Effort | `/effort`, флаг `--effort`, переменная `CLAUDE_CODE_EFFORT_LEVEL` (самый высокий приоритет), ключ `effortLevel` в settings.json (`low`, `medium`, `high`, `xhigh`; `max` для ключа не указан, есть `maxEffortLevel` как потолок). Если ничего не задано, дефолт модели: для Opus 5.5, Sonnet 5.5 и Haiku 5.5 это `medium` | [П] model-config, settings-reference |
| Какой файл настроек действует | `effortLevel` в **личном** `~/.claude/settings.json` Opus 5.5 и более новые модели **игнорируют**; в проектном, локальном, managed и в `--settings` ключ действует на все модели | [П] settings-reference (страница прочитана на 100 тыс. из 420 тыс. символов) |

### Облачная сессия
- **Файлами:** закоммитьте ключи в `.claude/settings.json` репозитория, но только если в сессии **один репозиторий**. Личные `~/.claude/settings.json` и `.claude/settings.local.json` облако не читает [П] code.claude.com/docs/en/settings, раздел «Settings in cloud sessions».
- **Переменными окружения облачной среды** (формат .env): `ANTHROPIC_MODEL`, `CLAUDE_CODE_EFFORT_LEVEL` и т.п. [П] cloud-environments.
- В интерфейсе приложения модель и effort можно выбрать в переключателе сессии [Н].
- **Ветку выбирайте до старта сессии.** Файлы агентов и настройки читаются при старте; агенты `combine-*`, появившиеся после смены ветки внутри сессии, не регистрируются как типы агентов [Н: наблюдалось в локальном запуске, облако не проверено].

### Субагенты
| Что | Как | Метка |
|---|---|---|
| Модель, порядок | параметр `model` при вызове, затем поле `model` во frontmatter (`inherit` = модель основной сессии), затем `CLAUDE_CODE_SUBAGENT_MODEL`, затем модель основной сессии. `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1` (v2.1.257+) перекрывает первые два | [П] sub-agents, model-config |
| Допустимые значения | алиасы `sonnet`, `opus`, `haiku`, `fable`; полный id; `inherit` | [П] sub-agents |
| Effort | поле `effort` во frontmatter (`low` ... `max`); `CLAUDE_CODE_EFFORT_LEVEL` **перекрывает** frontmatter у всех субагентов, поэтому его в облаке не задавать; параметр `effort` при вызове перекрывает frontmatter для не-fork субагентов (v2.1.292+) | [П] sub-agents |
| Субагенты из плагина | поле `model` разрешено; `hooks`, `mcpServers`, `permissionMode` игнорируются | [П] sub-agents |
| Где лежат | `.claude/agents/*.md` проекта подхватываются в облаке автоматически | [П] sub-agents, claude-code-on-the-web |

### Вложенность и оркестрация
- Субагент **может** вызывать субагентов: по умолчанию до трёх уровней ниже основной беседы (`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`, значение 1 отключает; v2.1.219+). До 20 одновременных субагентов (`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`) [П] sub-agents.
- Agent teams экспериментальные, включаются `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`; workflows (скрипт, оркестрирующий агентов) запускаются фразой «use a workflow» и работают в облаке [П] agent-teams, workflows.
- **Проверено у нас:** вложенный вызов работает в **локальной** среде [Н]. В облаке версия Claude Code и работа вложенности не проверены [НП] (эксперимент Э-1, `docs/EXPERIMENTS.md`).
- Что получает субагент: не историю беседы, а системный промпт агента, задание, CLAUDE.md, git status и предзагруженные скиллы. Ограничения на размер отчёта субагента в настройках нет: задавайте лимит в задании [П] sub-agents.

## 2. Как измерять расход (главный пробел)

**Официального способа получить расход конкретной облачной сессии (по моделям и по субагентам) программно нет** [П: CLI-reference и страницы cloud/costs прочитаны, подкоманд cost или status для облачных сессий нет].

| Способ | Что даёт | Ограничения |
|---|---|---|
| Панель Usage в приложении | стоимость сессии, доли по моделям, доли лимита по субагентам, кредиты облака | вручную; цифры накопленные за сессию; в наших замерах токены основной сессии не объяснили долю Sonnet в стоимости, «доля лимита» не равна доле стоимости [Н] |
| `/usage` (алиасы `/cost`, `/stats`) | оценка стоимости по прайсу, строка «Usage by model» (токены и доллары по моделям); на планах Pro/Max/Team процентная разбивка по навыкам, субагентам, плагинам и MCP | на Pro/Max стоимость «не имеет значения для счёта»; данные локальной истории; в облаке `/usage` в таблице команд не упомянут [П/НП] |
| Statusline | JSON со стоимостью (`cost.total_cost_usd`, оценка по прайсу), токенами, моделью; для субагентов отдельный `subagentStatusLine` с `tokenCount` и моделью | работает ли в облаке, не сказано [НП] |
| Хуки | `transcript_path` (путь к транскрипту), в `SubagentStop` ещё `agent_transcript_path` | в хуках нет стоимости; **формат транскрипта «внутренний, меняется между версиями»**, парсить ненадёжно [П] |
| OpenTelemetry | метрики `claude_code.cost.usage`, `claude_code.token.usage` (по моделям), события `claude_code.api_request` (модель, `cost_usd`, токены, `session.id`) | включается переменными окружения (в облаке задаются в облачной среде); из `.claude/settings.json` репозитория включить нельзя; нужен приёмник (collector) или Prometheus, доступный из сети сессии; входят ли запросы субагентов в `api_request`, явно не сказано [П/НП] |
| Analytics API, spend report | расход по пользователю или дню | не по сессии; для Team/Enterprise или Console |

**Что делаем сейчас:** снимок панели Usage до и после **каждой** сессии, цифры в журнал (`COST_LOG.md` проекта). Для сессии, которую продолжают, считаем прирост вычитанием и помечаем погрешность (проценты округлены). Если нужна автоматизация, единственный документированный путь это OTel с собственным коллектором в облачной среде [НП: не пробовали].

### Расчёт по токенам (оценка, не счёт)
Цены: platform.claude.com/docs/en/about-claude/pricing. Запись кэша на 5 минут 1,25×, на 1 час 2× от входной цены; чтение кэша 0,1× (для Opus 5.5 и Sonnet 5.5 0,05×, для Fable 5.1 0,025×) [П]. Вход = `input_tokens + cache_creation_input_tokens + cache_read_input_tokens`. По подписке основной TTL кэша 1 час, по API-ключу 5 минут (управляется `ENABLE_PROMPT_CACHING_1H`, `CLAUDE_CODE_PROMPT_CACHE_TTL`, `CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL`) [П]. Claude Code считает стоимость локально по прайсу; контрактные цены задаются только managed-настройкой `modelPricing` [П]. Как локальная оценка разделяет записи на 5 минут и на час, не описано [НП], поэтому расчёт из токенов даёт диапазон.
