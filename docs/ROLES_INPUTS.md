# Входные данные для анализа распределения ролей

Факты, собранные при первом запуске Комбайна в облаке, и пожелания владельца. Без деталей приватного проекта. Всё, что помечено «со слов» или «не проверено», проверяет анализ, а не принимает на веру.

## 1. Что запускалось (первый облачный прогон)
- Проект: сетевое приложение на Rust, задача этапов 2-5 по конвейеру: разведка и выбор базы, план этапов, каркас проекта, приёмка.
- Основная сессия: Sonnet 5.5 (дирижёр). Субагенты Комбайна: `combine-scout` (Haiku 5.5, low), `combine-architect` (Opus 5.5, high), `combine-skeleton` (Haiku 5.5, medium).
- Вызовы субагентов (из отчёта агента): scout ×3, architect ×2, skeleton ×1; `security` и `builder` не вызывались.
- Среда: облако Default (Trusted), веб ограничен (GitHub, docs.rs, сайты проектов были закрыты).

## 2. Расход (снято владельцем с панели Usage)
| Показатель | Значение |
|---|---|
| Стоимость сессии | $3,99 |
| Доля стоимости по моделям | Opus 71%, Sonnet 27%, Haiku 2% |
| Доля лимита по субагентам | architect 60%, skeleton 6%, scout 5% |
| Основная сессия | вход 50, выход 960, чтение кэша 2,1 млн, запись кэша 77 тыс. |
| Попадание в кэш | 96% |

Вывод владельца: Opus-архитектор получил основной объём работы, и это неправильное распределение.

## 3. Что наблюдалось
- Приёмку каркаса основная сессия сделала сама повторным запуском, а не по отчёту субагента: правило сработало. Независимая проверка в CI на трёх ОС подтвердила результат.
- Скауты и архитектор честно ставили метки «проверено / выведено / не проверено».
- План следующих 14 этапов, составленный архитектором, помечает 10 из них «ведёт architect, не builder» (то есть почти всё на Opus/high).
- Разведчик один раз скачал файл вне scratchpad (удалён); одно из ограничений запуска (ветка) агент обошёл правильно.
- Фактическую модель, обслужившую каждый субагент, агент не проверял (брал из frontmatter).

## 4. Пожелание владельца (со слов)
Сильная модель (Opus) не должна делать всё сама. Она должна брать дело в свои руки: декомпозиция, постановка задач более лёгким моделям, критерии приёмки, решения, ревью, сборка результата. Исполнение отдаётся builder и scout. Критичное (сеть, криптография, токены, разбор недоверенного ввода) исполняется не слабее Sonnet строго по спецификации и проходит ревью.

## 5. Известные ограничения (проверить)
- Предположение, **не проверено**: субагент не может сам вызывать других субагентов. Если так, то делегирование «Opus ставит задачи легким» возможно только когда Opus сам дирижёр (основная сессия).
- Основная сессия задаётся при запуске в приложении, а не файлами Комбайна.
- Профили моделей и цены: `docs/MODELS.md`, `core/models.json` (данные на 2026-10-09). Рекомендация Anthropic: исполнитель-Haiku или Sonnet без явной инструкции советника не вызывал ни разу в их измерениях (исследование в `docs/MODELS.md`).
- Замеры языков и токенизатора: `docs/EXPERIMENTS.md` (шумные, не вывод).
