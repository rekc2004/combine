# Комбайн (Combine)

**Что это.** Набор правил, агентов и скиллов для [Claude Code](https://code.claude.com/), который заставляет сессию работать как небольшая команда: дешёвые модели ищут и строят каркас, сильные проектируют и проверяют безопасность, а состояние задачи лежит в файле и не пропадает при `/compact` или в новой сессии.

**Зачем.** Две типичные проблемы больших проектов:
1. **Дорого и медленно.** Сильная модель тратит время на поиск по репозиторию, а слабая пытается написать сложное ядро целиком. Оба варианта неэффективны.
2. **Модель забывает правила.** Ваши договорённости («сначала переспроси, потом делай», «без посредников») теряются между сессиями и после сжатия контекста.

**Как работает.** Комбайн копируется в ваш проект обычными файлами: `CLAUDE.md`-блок, `.claude/agents`, `.claude/skills`, хуки. Поэтому он работает и **локально, и в облачных сессиях** (в облаке плагины из репозитория не ставятся, а файлы самого проекта подхватываются).

> Статус: ранняя версия. Скрипты проверены локально на тестовом проекте. В живой сессии Claude Code и в облаке целиком **ещё не проверено**, см. «Что не проверено».

## Как устроена работа
1. **Диалог.** Модель уточняет задачу и ничего не пишет, пока вы не ответили.
2. **План.** Задача режется на этапы. Для каждого оркестратор сам выбирает модель и effort, взвешивая профили моделей ([откуда они](docs/MODELS.md)).
3. **Скелет.** Дешёвая модель строит каркас; главная сессия сама проверяет, что он собирается и тесты проходят.
4. **Наращивание.** Сильные модели добавляют сложное поверх проверенного каркаса.
5. **Проверка.** Отдельный агент смотрит безопасность; в отчёте честно написано, что не проверено.

Состояние живёт в `docs/TASK.md`, хук подгружает его на старте сессии и после компакта.

## Подключение
```bash
git clone https://github.com/rekc2004/combine
cd combine
git checkout <тег>                               # закрепите версию, не берите «последнюю»
python tools/sync.py --target /путь/к/проекту --dry-run   # посмотреть, что изменится
python tools/sync.py --target /путь/к/проекту
```
Повторный запуск обновляет. Проверить, что файлы в проекте не менялись руками: `python tools/sync.py --target . --check`.

**Одной фразой в сессии (в том числе облачной):**
> Подключи Комбайн: склонируй https://github.com/rekc2004/combine в папку ВНЕ проекта, переключись на тег `vX.Y.Z`, прочитай `tools/sync.py` и хуки, потом запусти `python -I tools/sync.py --target <корень проекта>` и закоммить результат.

## Ключи: что можно включать и отключать
Каждая часть комбайна имеет **ключ**. Ключ можно отключить при подключении (`--without`), включить то, что выключено по умолчанию (`--with`), и выбрать наборы скиллов (`--packs`). Пример:
```bash
python tools/sync.py --target . --packs technical,review --with review.deep --without hook-guard
```

### Ядро (модули)
| Ключ | Что делает | По умолчанию |
|---|---|---|
| `core` | Правила поведения: сначала пойми и переспроси, не нарушай ваши исходные ограничения, честно о непроверенном | да |
| `pipeline` | Конвейер этапов и шаблон `docs/TASK.md` | да |
| `agents` | Агенты `scout` (поиск), `skeleton` (каркас), `builder` (реализация), `architect` (проектирование), `security` (ревью безопасности) с моделью и effort | да |
| `hook-state` | Подгружает `docs/TASK.md` на старте, после компакта, resume | да |
| `hook-guard` | Блокирует очевидно разрушительные команды (`rm -rf /`, force-push в main, `curl \| sh`). Только классические формы, не песочница | да |
| `hook-remind` | Короткое напоминание правил в каждом запросе. Дублирует `CLAUDE.md`, тратит токены, поэтому выключено | нет, `--with hook-remind` |

### Скиллы (наборы)
Скиллы лежат группами в папках [`skills/`](skills/). Проект выбирает наборы: техническому не нужна графика, визуальному не нужны инженерные скиллы. Дорогие скиллы (в описании `[дорого]`) ставятся только по явному `--with` и вызываются только по вашей просьбе. Таблица ниже генерируется скриптом `tools/check.py`:

| Ключ | Стоимость | Ставится по умолчанию | Что делает | Лицензия |
|---|---|---|---|---|
| `review.quick` | дёшево | да | Быстрое ревью своих изменений по короткому чек-листу перед коммитом. | свой |
| `technical.simple-and-surgical` | дёшево | да | Писать минимум кода под задачу, менять только нужное, заранее задавать проверяемые критерии успеха. | свой |
| `technical.verify-done` | дёшево | да | Перед тем как сказать «готово» про код: собрать, запустить тесты, показать фактический результат. | свой |

### Что можно выключить на старте сессии, а что нет
- `COMBINE_DISABLE=hook-guard,hook-state` (или `all` для всех трёх хуков) **жёстко** выключает хуки: они читают переменную и завершаются без вывода.
- Для правил, конвейера, агентов и скиллов переменная — только **подсказка модели** «не использовать». Файлы лежат в проекте, и их описания всё равно попадают в контекст. Жёстко убирает только `--without` при подключении.
- В одном чате: напишите **«не используй комбайн»**, вернуть: **«включи комбайн»**.
- В облаке переменные окружения задаются в настройках облачного окружения; дойдут ли они до хуков, **не проверено**.

## Модели
Таблица «модель, класс работ, effort» живёт в [`core/models.json`](core/models.json): профили (сильные и слабые стороны, цена, скорость), и агенты с моделью и effort. Вышла новая модель — правите файл и запускаете `sync.py`. Профили собраны из документации Anthropic и независимых измерений на 2026-10-09 ([docs/MODELS.md](docs/MODELS.md)); это стартовые оценки, а не бенчмарки вашего проекта.

## Безопасность
- Репозиторий публичный, а `sync.py` копирует из него инструкции и хуки в ваши проекты. Кто получит запись в него, тот сможет выполнять команды в ваших проектах. Включите двухфакторную защиту на GitHub, не принимайте чужие PR, не прочитав, **подключайте по тегу или коммиту**, а перед обновлением смотрите diff.
- Наборы скиллов могут содержать только `.md`/`.txt` из списка `files`. Скриптов, хуков, настроек и агентов из наборов поставить нельзя. Для скиллов проверяется путь (без `..` и абсолютных).
- `sync.py` пишет только внутри целевого проекта, не перезаписывает чужие файлы с теми же именами, отказывается работать с повреждённым `settings.json`, хранит `.combine.lock` с контрольными суммами (проверка: `--check`).
- Скилл читает модель, поэтому читайте каждый скилл целиком, прежде чем добавить; в репозиторий нельзя класть токены и личные данные.

## Что не проверено
- Хуки, агенты и скиллы запускались только скриптами локально, не в живой сессии Claude Code.
- Облачные сессии: по документации подхватываются `CLAUDE.md`, `.claude/agents`, `.claude/skills`, `.claude/settings.json` с хуками из репозитория проекта. В них Комбайн ещё не запускался. Нужен Python (хуки пробуют `python3`, потом `python`); на Windows хуки идут через `sh`, что не проверено на чистой установке.
- Поле `effort` и полные id моделей в агентах взяты из документации; проверьте актуальность.
- Будет ли дешёвая модель на этапе «скелет» экономить деньги в реальных проектах, пока гипотеза.
