# Комбайн (Combine)

**Что это.** Набор правил, агентов и скиллов для [Claude Code](https://code.claude.com/) и Kimi Code, который заставляет сессию работать как небольшая команда: поиск, архитектура, реализация и проверка разделены по ролям, а состояние задачи лежит в файле и не пропадает при `/compact` или в новой сессии. Общий конвейер один; платформенные возможности добавляются адаптерами.

**Зачем.** Две типичные проблемы больших проектов:
1. **Дорого и медленно.** Сильная модель тратит время на поиск по репозиторию, а слабая пытается написать сложное ядро целиком. Оба варианта неэффективны.
2. **Модель забывает правила.** Ваши договорённости («сначала переспроси, потом делай», «без посредников») теряются между сессиями и после сжатия контекста.

**Как работает.** Два способа подключения:
- **Копией в проект** (`--target`): обычные файлы в проекте (`CLAUDE.md`-блок, `.claude/agents`, `.claude/skills`, хуки). Так он работает и **локально, и в облачных сессиях** (в облаке плагины из репозитория не ставятся, а файлы самого проекта подхватываются).
- **Глобально для всех ваших локальных сессий** (`--user`): ставится один раз в `~/.claude`, ничего не копируется в проекты, включён везде, пока в проекте не сказано «выключи» (`/combine off`). Облако `~/.claude` не читает, поэтому для облака остаётся копия в проект.

Внутренние тексты (правила, шаблоны, описания агентов и скиллов) написаны на сжатом английском: по замеру он на 31% дешевле русского по токенам при том же соблюдении правил. Выводы и отчёты вам модель по-прежнему пишет на вашем языке.

> Статус: ранняя версия. Установка (оба способа) и хуки проверены локально на Windows в живых сессиях Claude Code; в облаке Комбайн целиком **ещё не проверен**, см. «Что не проверено».

## Быстрый старт
Нужны Python 3 и git. Всегда берите **выпущенный тег** (последний: [Releases](https://github.com/rekc2004/combine/releases/latest)), не `main` и не чужую ветку.

**Локально, во всех ваших сессиях Claude Code** (один раз на компьютер):
```bash
git clone https://github.com/rekc2004/combine
cd combine
git checkout <последний тег, например v0.3.2>
python tools/sync.py --user --dry-run   # посмотреть, что будет записано в ~/.claude
python tools/sync.py --user             # поставить
```
Дальше в любой сессии: **`/combine`** (статус), **`/combine update`** (обновить целиком до последнего тега, с показом diff и вашим подтверждением), **`/combine off`** (выключить для проекта), **`/combine here`** (подключить копией в проект). Проверка: `/combine status`.

**В облачной сессии** (облако не читает `~/.claude`, поэтому копия в проект; команды отправляете вы в сессию проекта):
> Подключи Комбайн: склонируй https://github.com/rekc2004/combine в папку ВНЕ проекта, переключись на тег `<последний тег>`, прочитай `tools/sync.py` и хуки, запусти `python -I tools/sync.py --target <корень проекта> --dry-run`, затем без `--dry-run` и `--check`, закоммить результат. Если классификатор прав блокирует `sync.py`, ничего не обходи и остановись.

Обновление копии в проекте: та же фраза с новым тегом. Подробности, ключи и безопасность ниже.

**Kimi Code:** `python tools/build_plugin.py`, затем в TUI `/plugins install <путь>/dist/kimi-plugin` и `/reload`. Сборка добавляет Kimi-адаптер: роли и изолированные контексты субагентов вместо обязательного выбора модели. Для независимых implementation missions владелец может отдельно включить экспериментальный Tower с branch/worktree на mission; Combine не включает его сам. Tower workers/reviewers работают с Never Ask permissions, поэтому применять только в доверенном репозитории и с узкими mission scopes.

TRIZ включён по умолчанию. Жёсткое отключение в Claude: `--without triz`; вернуть: `--with triz`. В Kimi жёсткое off: `python tools/build_plugin.py --without triz` и переустановка; `COMBINE_DISABLE=triz` — мягкое отключение на сессию.

## Как устроена работа
1. **Диалог.** Модель уточняет задачу и ничего не пишет, пока вы не ответили.
2. **Анализ задачи.** Фиксируются факты, неизвестное и критерии результата. Обычная ясная задача идёт дальше сразу; при противоречии или тупике навигатор ТРИЗ открывает один маршрут за раз, без загрузки всего пакета.
3. **План.** Задача режется на этапы с владельцем и критерием готовности. Правильная архитектура и сохранённые решения важнее настройки модели; ненужные этапы ТРИЗ вычёркиваются.
4. **Скелет.** Дешёвая модель строит каркас; главная сессия сама проверяет, что он собирается и тесты проходят.
5. **Наращивание.** Сильные модели добавляют сложное поверх проверенного каркаса.
6. **Проверка.** Отдельный агент смотрит безопасность; в отчёте честно написано, что не проверено. Если применялся ТРИЗ, дополнительно проверяется снятие исходного противоречия.

Состояние задачи живёт в `docs/TASK.md`, а устойчивые архитектурные правила и расположение программ/моделей — в корневом `PROJECT.md`. Хук подгружает оба на старте и после компакта. `PROJECT.md` создаётся один раз, при обновлении не перезаписывается, новые инструменты добавляются без сокращения файла; секреты и код там запрещены. В release попадает только пустой шаблон, данные проекта — никогда.

Для сравнения вариантов используются временные копии отдельных файлов и diff; оригинал меняется только после выбора и проверки. Работа самостоятельного этапа может идти в изолированном контексте субагента, а в главный чат возвращаются только результат, изменённые файлы, проверки и ограничения.

Проверенные ошибки превращаются в уроки с версией среды, причиной, безопасным правилом, проверкой и областью применимости. Проектные уроки остаются в `PROJECT.md`; обобщённые и обезличенные — в общем для Claude/Kimi `~/.combine/LESSONS.md` (можно изменить через `COMBINE_HOME`). Главная сессия проверяет урок перед записью; приватные пути, код и данные проектов в общую память и релизы не попадают. Перед написанием нового helper Combine сначала смотрит каталог PROJECT и граф, чтобы адаптировать существующую проверенную функцию, если не требуется независимая реализация.

Общий `~/.combine/TOOLS.json` хранит точные расположения программ, моделей и ресурсов во всех проектах: назначение, путь/команду, причину использования, ограничения и проверку. `registry.py find ffmpeg` ищет по имени, псевдонимам и полям без embeddings; `--project <корень>` добавляет поиск по локальному PROJECT. `registry.py upsert` атомарно добавляет/обновляет одну запись, не трогая остальные. Настоящий реестр не публикуется; в release входит только пустой шаблон.

## Подключение
```bash
git clone https://github.com/rekc2004/combine
cd combine
git checkout <тег>                               # закрепите версию, не берите «последнюю»
python tools/sync.py --target /путь/к/проекту --dry-run   # посмотреть, что изменится
python tools/sync.py --target /путь/к/проекту
```
Повторный запуск обновляет. Проверить, что файлы в проекте не менялись руками: `python tools/sync.py --target . --check`. Контрактные регрессии на временных проектах: `python tools/self_test.py` (rollback, TRIZ switch, dirty release, graph atomicity, plugin layout).

**Одной фразой в сессии (в том числе облачной):**
> Подключи Комбайн: склонируй https://github.com/rekc2004/combine в папку ВНЕ проекта, переключись на тег `vX.Y.Z`, прочитай `tools/sync.py` и хуки, потом запусти `python -I tools/sync.py --target <корень проекта>` и закоммить результат.

### Глобально, для всех проектов на этом компьютере
```bash
python tools/sync.py --user --dry-run     # посмотреть: файлы в ~/.claude и три записи хуков в ~/.claude/settings.json
python tools/sync.py --user               # поставить
python tools/sync.py --user --status      # что установлено
python tools/sync.py --user --uninstall   # убрать (чужие ключи и хуки в settings.json не трогаются)
```
Перед первой установкой сделайте копию `~/.claude/settings.json`. После установки в любой сессии доступна команда **`/combine`**: `status`, `off` (выключить Комбайн для текущего проекта: файл `.claude/combine-off`), `on`, `here` (подключить копией в проект, нужно для облака), `update` (обновить всё целиком до последнего выпущенного тега из любого окна: показывает diff и CHANGELOG, ставит после вашего подтверждения; копия продукта ведётся в `~/.claude/combine/src`). Правила подаёт хук старта сессии (около 2 тыс. токенов на сессию), `CLAUDE.md` проектов не меняется. Если в проекте уже есть своя копия Комбайна, глобальные хуки молчат. Установщик отказывается ставить Комбайн в репозиторий самого Комбайна.

## Ключи: что можно включать и отключать
Каждая часть комбайна имеет **ключ**. Ключ можно отключить при подключении (`--without`), включить то, что выключено по умолчанию (`--with`), и выбрать наборы скиллов (`--packs`). Пример:
```bash
python tools/sync.py --target . --packs technical,review,triz --with review.deep --without hook-guard
```

При обновлении старой установки прежний выбор `packs` сохраняется. Чтобы явно добавить TRIZ, повторите команду с `--packs technical,review,triz` (для глобальной установки — с `--user`). Sync печатает такую подсказку и не меняет пользовательский выбор молча.

### Ядро (модули)
| Ключ | Что делает | По умолчанию |
|---|---|---|
| `core` | Правила поведения: сначала пойми и переспроси, не нарушай ваши исходные ограничения, честно о непроверенном | да |
| `pipeline` | Конвейер этапов и шаблон `docs/TASK.md` | да |
| `agents` | Агенты `scout` (поиск), `skeleton` (каркас), `builder` (реализация), `architect` (проектирование), `security` (ревью безопасности) с моделью и effort | да |
| `hook-state` | Подгружает `docs/TASK.md` и ограниченный `PROJECT.md` на старте, после компакта, resume | да |
| `hook-guard` | Блокирует очевидно разрушительные команды (`rm -rf /`, force-push в main, `curl \| sh`). Только классические формы, не песочница | да |
| `hook-compact` | После сжатия контекста (ручного и автоматического) сохраняет сводку в `.claude/combine/compactions/` (не в git, 10 последних); после сжатия хук старта напоминает, где она. Порог автосжатия не меняет | да |
| `graph` | Граф кода: на старте сессии и после сжатия строит в фоне `docs/GRAPH.md` (области, связи, главные файлы и функции, до 160 строк) и `.claude/combine/graph.json`; точные вопросы — `python ~/.claude/combine/graph/query.py users|deps <файл>`, `callers|calls|find <имя>`. Разбирает TS/JS, Python (и скрипты без расширения с `#!…python`), C/C++. Только стандартная библиотека Python. Подробно: [docs/GRAPH-MODULE.md](docs/GRAPH-MODULE.md) | да |
| `hook-remind` | Короткое напоминание правил в каждом запросе. Дублирует `CLAUDE.md`, тратит токены, поэтому выключено | нет, `--with hook-remind` |
| `triz` | Условный анализ противоречий; при off pipeline использует main/architect без TRIZ | да, `--without triz` выключает весь набор |

### Что можно выключить на старте сессии, а что нет
- `COMBINE_DISABLE=hook-guard,hook-state` (или `all` для всех хуков) **жёстко** выключает хуки: они читают переменную и завершаются без вывода.
- Для правил, конвейера, агентов и скиллов переменная — только **подсказка модели** «не использовать». Файлы лежат в проекте, и их описания всё равно попадают в контекст. Жёстко убирает только `--without` при подключении.
- В одном чате: напишите **«не используй комбайн»**, вернуть: **«включи комбайн»**.
- В облаке переменные окружения задаются в настройках облачного окружения; дойдут ли они до хуков, **не проверено**.

## Модели
Роли и доступные host-контроли живут в [`core/agents.json`](core/agents.json). Для Claude там же заданы модели и effort; Kimi использует роли, инструменты и ограничения, а необязательный model pool настраивается отдельно. Выбор модели — вторичный рычаг: основная экономия достигается правильной архитектурой, TASK/графом и отсутствием повторного поиска. Профили моделей собраны на 2026-10-09 ([docs/MODELS.md](docs/MODELS.md)); это стартовые оценки, а не бенчмарки проекта.

## Безопасность
- Репозиторий публичный, а `sync.py` копирует из него инструкции и хуки в ваши проекты. Кто получит запись в него, тот сможет выполнять команды в ваших проектах. Включите двухфакторную защиту на GitHub, не принимайте чужие PR, не прочитав, **подключайте по тегу или коммиту**, а перед обновлением смотрите diff.
- Наборы скиллов могут содержать только `.md`/`.txt` из списка `files`. Скриптов, хуков, настроек и агентов из наборов поставить нельзя. Для скиллов проверяется путь (без `..` и абсолютных).
- `sync.py` пишет только внутри целевого проекта, не перезаписывает чужие файлы с теми же именами, отказывается работать с повреждённым `settings.json`, хранит `.combine.lock` с контрольными суммами (проверка: `--check`).
- Глобальная установка (`--user`) пишет в вашу `~/.claude`: добавляет файлы и три записи хуков в `settings.json` (остальное не трогает) и учитывает свои файлы в `~/.claude/combine/lock.json`. Хук-охранник работает во всех проектах и может блокировать команды; выключается `/combine off` или `--without hook-guard`.
- Скилл читает модель, поэтому читайте каждый скилл целиком, прежде чем добавить; в репозиторий нельзя класть токены и личные данные.

## Что не проверено
- Проверено на Windows в живых локальных сессиях: глобальная установка, хук старта подаёт правила, `/combine status`, появление скиллов и агентов в уже идущей сессии. Хук сохранения сводки проверен на ручном `/compact`; на автосжатии и в облаке не проверен. Не проверено: работа самих агентов `combine-*` в субагентах и расход токенов за длительное время.
- Облачные сессии: по документации подхватываются `CLAUDE.md`, `.claude/agents`, `.claude/skills`, `.claude/settings.json` с хуками из репозитория проекта. В них Комбайн ещё не запускался. Нужен Python (хуки пробуют `python3`, потом `python`). В облаке автоматический классификатор прав может заблокировать установку `sync.py`, тогда нужно разовое разрешение в диалоге.
- Граф кода проверен на одном проекте (~200 файлов TS/C/Python): на 6 точных вопросах агент поиска с графом тратил ~15% меньше токенов и вдвое меньше вызовов, ответы одинаково верны; по одному прогону, разброс не измерен. Вызовы в TS/JS/C сопоставляются по имени; shell-скрипты в граф не входят.
- Поле `effort` и полные id моделей в агентах взяты из документации; проверьте актуальность.
- Будет ли дешёвая модель на этапе «скелет» экономить деньги в реальных проектах, пока гипотеза.
