# M1. Mini-task and X/Y Pair

Mini-task: "In ___, when ___, I need ___, but ___." Keep the user's hard constraints unchanged.

Then name:
- **X:** parameter/property to improve;
- **Y:** parameter/property that worsens;
- **same changing element:** what actually has opposite states.

Use nouns without evaluations ("validation latency", "retained bytes", "result freshness"), not "bad cache" or "slow code".

Gate: a bare X/Y pair is only a symptom. Use A1 when the interacting tool/object or opposite states are unclear; use A4 when both opposite demands are already evident.
