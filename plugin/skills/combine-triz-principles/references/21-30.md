# Principles 21–30

| № | Principle | AI-task transformation |
|---|---|---|
| 21 | Skipping | Perform a harmful stage at high speed only when exposure is bounded, reversible or sandboxed: one rapid pass that reduces damage. Never accelerate irreversible production/security actions or skip approval. A mere rough draft is P16. |
| 22 | Blessing in disguise | Use a harmful factor for a positive effect, combine harms to cancel them, or intensify a harm until it disappears: failures become tests; hostile inputs become fixtures. |
| 23 | Feedback | Measure the output and return it to the control rule; change the next action from evidence, not from a fixed checklist alone. |
| 24 | Intermediary | Insert a temporary carrier/mediator between objects: adapter, index, buffer, or representative sample that enables interaction and can be removed. |
| 25 | Self-service | Let the system perform auxiliary service on itself and use its byproducts: self-check, self-repair, regenerate state, reuse logs/traces for maintenance. |
| 26 | Copying | Replace an expensive/fragile/unavailable original with a copy or model: dry-run, mock, fixture, isolated branch. |
| 27 | Cheap short-living objects | Replace an expensive durable object with cheap disposable ones: one-off script or temporary artifact, removed after its function is complete. |
| 28 | Mechanics substitution | Replace the class of interaction, not just the algorithm: direct mechanical/rule manipulation → model, signal, index, event, or other field-like non-contact action. |
| 29 | Pneumatics and hydraulics | Replace rigid solid coupling with a flow/pressure-like medium: event/data streams or queues that decouple parts; do not add a queue solely for fashion. |
| 30 | Flexible shells and thin films | Isolate or connect with a thin flexible layer: minimal adapter/wrapper/interface around an external object. |

Gate: state what class of interaction changed. If any method would fit the explanation, the transformation is too vague.
