# A8–A9: Reframe or Check

## A8. Change/replace a blocked task
Use only when no acceptable answer emerged or A9 failed:
1. If a physical/conceptual answer exists, turn it into a concrete implementable mechanism and tests (canonical 6.1).
2. Split a statement that combines several tasks; solve the main one first (6.2).
3. Return to A1 and choose the other TP/main-function branch (6.3).
4. Reframe in the supersystem, where a new resource or function may remove the conflict (6.4).

Do not silently relax the user's hard constraints. If reframing changes the requested outcome, return to Combine Dialogue.

## A9. Check the answer
Ask and provide evidence:
1. Is the main IFR requirement met, including preservation of the useful action?
2. Which exact FP was eliminated, and how? Was harm merely moved to another subsystem?
3. Is at least one element controllable, with a clear control signal?
4. Does the answer survive repeated cycles, not just one demonstration?
5. Are new components/resources necessary, or can existing/self-regulating resources replace them?
6. What implementation, calculation, organizational, and verification subtasks remain?

Patent novelty is irrelevant to an internal engineering task unless the user requests it.

Gate: failed A9 → A8 or A1 with the failed criterion recorded. Passed A9 → return to Combine Plan/Build-up with stage-level acceptance criteria. Load `05-apply-learn.md` only after a verified answer when transfer or learning is useful.
