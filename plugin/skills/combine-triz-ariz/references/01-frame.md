# A1–A2: Frame the Task

## A1. Mini-task and conflict model
Use plain language; replace solution-shaped jargon with what the element actually does.

1. **System:** purpose and only the interacting parts needed for the conflict.
2. **Conflicting pair:** object/artifact being changed and the tool/mechanism acting directly on it.
3. **TP-1:** one state of the tool gives useful action U but also harm H.
4. **TP-2:** the opposite state removes H but loses U or creates another harm. Do not replace the pair with an "optimal middle".
5. **Main function:** choose the TP whose state best preserves the system's main useful function.
6. **Intensify:** push the chosen state toward its limit (zero/absent/complete where meaningful).
7. **X-element:** name the unknown change that preserves the useful property and removes the harm with minimal system change.

Output: a compact block containing pair, TP-1/TP-2, main function, intensified state, and X-element requirement. If opposite states cannot be written, return to Combine Dialogue or reframe; do not invent a contradiction.

## A2. Operational zone and time
- **OZ:** exact context, artifact, interface, or interaction where the conflict occurs.
- **T1:** time during the conflict.
- **T2:** available time before the conflict, when prevention may be cheaper.

Gate: record A1/A2 in TASK.md. With a clear model, read `02-ideal.md`; if the goal or constraints are unclear, return to Dialogue.
